# `wl console` 与 Orca 插件：功能对齐表

- 日期：2026-11-07
- 状态：随插件演进更新（当前对齐到插件 P1 末：岗位详情 / 时间线已上线）
- 结论速览：**读侧插件已覆盖 console 的核心页面；写侧覆盖了高频三件（回答 / 冻结解冻 / 认领完成）；编辑器与生命周期管理仍归 console。**
- 依据：3B spec（页面清单 §范围）、3C（编辑器 / TUI）、3E（全生命周期 UI 意图）、插件 spec `2026-11-06-orca-plugin-console-design.md` §7/§15

## 1. 读侧（页面 / 视图）

| console 页面 | 3B/3E 内容 | 插件对应 | 状态 |
|--------------|-----------|----------|------|
| 总览 | 团队列表、岗位数、调度员状态、待处理计数 | 团队卡片（名称 + up/stopped 徽标 + 岗位数 + pending 徽标） | ✅ 已覆盖 |
| 收件箱 | 冻结 / 信号 / 提问 / 滞留 / 警告 / 取不到的来源 | 团队卡片 → 收件箱视图（逐条列出 + 计数） | ✅ 已覆盖 |
| 任务看板 | 任务列表（状态 / 认领人 / 标签 / 滞留） | 团队卡片 → 任务视图（标题 / 状态 / 认领人） + **任务详情**（计划 / 历史 / gate 输出尾部） | 🟡 部分：无标签列、无 `--stale` 专列、无分页 |
| 任务详情 | 计划、历史、gate 输出路径、结果 | ❌ 无 | ❌ 缺 |
| 岗位详情 | 当前任务、排队、信号、冻结 / 静音、终端预览 40 行、时间线 50 条 | 团队卡片 → 岗位 → 详情（当前任务 / 排队 / 信号 / 冻结 / 静音 / 时间线 50 条取最近 12 条） + 独立的「预览」 | ✅ 已覆盖（时间线显示条数比 console 少） |

| 设置 / 关于（3C/3E） | 版本、Orca 路径、console 文件 | ❌ 无 | ❌ 缺 |
| 新建团队 / 生命周期按钮（3E） | init / up / down / restore / dispatcher up·down / autostart | ❌ 无 | ❌ 缺（有意后置） |

## 2. 写侧（操作）

| 操作 | console（3B/3E） | 插件 | 状态 |
|------|------------------|------|------|
| 回答提问 | ✅（`console: dispatcher reply`） | ✅（`plugin: dispatcher reply`） | ✅ |
| 冻结 / 解冻岗位 | ✅ | ✅ | ✅ |
| 认领 / 放弃 / 计划 / 开始 / 完成 | ✅（带「以岗位身份」） | 🟡 认领 / 完成（`--as` 手输）；放弃 / 计划 / 开始 ❌ | 🟡 部分 |
| 建任务 / 改派 / recover / resolveGate | ✅ | ❌ | ❌ 缺 |
| 给岗位发消息（send） | ✅ | ❌ | ❌ 缺 |
| hush / unhush | ✅ | ❌ | ❌ 缺 |
| 规格（spec）读 / 校验 / 保存 / 丢草稿 | ✅ | 🟡 worker 已有 `spec.readForEdit`（3C 保存走 `createSpecFacade`，面板未接） | 🟡 地基已备 |
| up / down / restore / 调度员启停（3E） | ✅ | ❌ | ❌ 缺（有意后置） |
| init / autostart（3E） | ✅ | ❌ | ❌ 缺（有意后置） |

**审计**：两边同一张 core 审计表、同一 actor（`human`），仅来源前缀不同（`console:` / `plugin:`）。见插件 spec §15.3。

## 3. 体验差异（有意不同）

| 维度 | console | 插件 | 说明 |
|------|---------|------|------|
| 宿主 | 本机 HTTP + Orca 内置浏览器标签 | Orca 侧栏常驻 | 插件免登录、免起服务 |
| 实时刷新 | SSE 推送 | **worker 30s 轮询 + `panels.post` 推送**（`inbox.changed` / `tasks.changed` / `posts.changed`，内容变了才推）+ 手动刷新 | 已有推送式刷新，粒度 30s |
| 布局 | 桌面浏览器宽屏多页 | 347px 窄侧栏，一次一个团队 | 插件信息密度让位于可达性 |
| 打开终端 | 「发消息」入口打字 | 「打开终端」直接把 Orca 窗口切到该终端 | 插件靠 `orca terminal switch` |
| Orca 界面同步（3C：标题 / 卡片状态行 / 未读） | ❌（归 3C） | 部分（状态条待处理数） | 各自都不完整 |

## 4. 结论与路线

1. **读侧**：插件已能替代 console 的日常值班浏览（总览 / 收件箱 / 岗位 / 任务）。
2. **写侧**：高频处置（回答 / 冻结解冻 / 认领完成）插件已够用；**建任务 / 改派 / resolveGate / send** 等低频重操作仍走 console 或 CLI。
3. **编辑器与生命周期**：继续归 console（3C/3E 已实现且体验更完整）；插件侧等 Phase 3（components 编辑器）再评估。
4. **SSE 等价物**：✅ 已实现——worker 30s 轮询 + `panels.post`（`inbox.changed` / `tasks.changed` / `posts.changed`），内容变化才推。
5. `wl console` **保留**：无 Orca 环境、宽屏多页浏览、编辑器与生命周期管理的主入口。
